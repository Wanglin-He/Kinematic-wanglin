kinematic_claims · 我们这一环的输入

八张卡里唯一进入 P3 的。下面是它的每个子字段。

canonical_frame补
up: gravity ← 总是可用，免费 front: null | 部件 id ← 没锚定则 numeric 轴向记 N/A
joints[].axis改

原写法 axis: depth，而方案从未定义物体坐标系。

三选一，至少给一种： semantic: vertical | horizontal ← 对重力算 relational: 部件之间的关系 ← 免坐标系 numeric: [x,y,z] ← front 未锚定 → N/A

joints[].anchor改

实测：关节 pos 挪 0.25 m，子部件位移 slide 0.000000 hinge 0.171449 ball 0.191345 free 0.000000 ⇒ 只对 hinge / ball 可检，slide / free 恒 N/A

  dependent:   gear_small_spin
  independent: gear_large_spin
  coefficient: -3.0   # 外啮合反转，负号是机构不是约定

asset_states补

joints[].states 是每个关节自己的标签，而 contact_policy 当整机属性用。

q ∈ 状态 s ⟺ ∀ j ∈ scope(s): |q_j − states_j[s]| ≤ τ_rel × span_j scope = named_parts | all_declaring
容差不能省：若要求精确相等，连续采样里合格样本可能一个都没有， 那条声明永远不被检查——而这会读成通过。
contact_policy改

原方案 allowed/forbidden，但从没说 allowed 断言什么。

required:   # 义务：该状态必须接触
  - {parts: [door, cabinet_body], state: closed,
     relation: stop_contact}
permitted:  # 许可：接触不违规，不接触也不失败
forbidden:  # 禁止：全程不得穿模超阈值
  - {parts: [door, drawer_1], state: all}
precedence: required_and_permitted_over_forbidden
当成「允许」→ 永远不会失败，对分数零贡献；当成「必须」→ 需要接触容差和状态判定，两个都不存在。 后果：没有任何检查要求声明的止挡真的发生。
优先级也不是可有可无——原示例把同一对同时放进两个桶，S_collision 在采样端点上没有定义。
tolerances补

原方案一个容差字段都没有，13 个阈值实际由写代码的人默默决定。

axis_angle_deg 15.0 anchor_edge_inset_max 0.15 anchor_center_offset_max 0.05 travel_scale_min 0.50 follower_drift_m 0.0005 state_match_relative 0.02 required_contact_m 0.002 forbidden_penetration_m 0.001 coupling_residual 0.02

A1 有实测依据。上一轮用文字部件名匹配代码标识符：70 次报警 63 次误报， 其中 42 次是「找不到零件」——但 7 个真问题里也有 4 个来自同一信号。信号和噪声是同一件事， 配对 bootstrap 的 Δκ 95% 区间含零，写更好的匹配器救不了。A1 把「契约写错」这个可能性在生成之前消掉。

每条规则配一个测试，只破坏标准契约的一处，断言它被触发。触发不了的规则等于没写。

共用前提：绑定 b*(P) 由 Gate 给出，P3 只读不猜名字 · 参考姿态 q_ref = closed → home → range.min · 距离一律 mj_geomDistance

KF1 · 关节配置保真度

Articulation Specification Fidelity — 9 条

parent照做
A(b) = 沿 body_parentid 上溯遇到的 第一个已绑定部件 通过 ⟺ A(b*(part)) = parent
不是「是不是祖先」：挂在上抽屉下的下抽屉，柜体仍在祖先链上， 问「在不在上面」会放过「拉开上抽屉把下抽屉一起拖出来」。未声明的中间 body 透明跳过。
type照做
μ: slide↦mjJNT_SLIDE, hinge↦mjJNT_HINGE, ball↦mjJNT_BALL, free↦mjJNT_FREE 通过 ⟺ jnt_type[k] = μ(声明)
本组最弱，明说：6 条记录声明与提示词一字不差、人还是判失败。 归进「读字段」子分数单独报，不冲淡测量类。
dof_composition改
通过 ⟺ body_jntnum[b*(part)] = 1
原第 4 条两半都永远不会失败：「slide 不得产生旋转」——slide 按定义就是纯平移； 「hinge 锚点在扰动下固定」——mj_kinematics 就是按声明的 jnt_pos 算出锚点的。 数关节个数才是模型真能做错的。
axis_semantic照做
û = −g/|g| g = opt.gravity â = xaxis[k]/|xaxis[k]| 世界系 c = |â · û| vertical 通过 ⟺ c ≥ cos(15°) horizontal 通过 ⟺ c ≤ sin(15°)
唯一不需要物体坐标系的方向判定，整机绕竖直轴转不改变结果。 它自己承认看不见更细的方向：往侧面滑和往外滑都是水平的。
axis_admits_motion补
d₀ = 部件与父件在 q_ref 的最小带符号距离 若 d₀ < −ε → N/A（本来就卡在一起， 每个方向都会撞，是静态几何的账） δ = min(0.25 × 行程, 0.05) q ← q_ref + δ×声明轴向 ; mj_forward 通过 ⟺ d₁ ≥ −ε
更细方向唯一不依赖坐标系的证据：往这个方向走得通吗。 抓抽屉往侧面滑撞进左墙——axis_semantic 看不见。
anchor改×2
on_edge_of: r_i = (p_i−p₀) − ((p_i−p₀)·â)â s_i = r_i · d d = 质心径向 inset = min(|min s|,|max s|) / (max s − min s) 通过 ⟺ inset ≤ 0.15 0=在边上 0.5=正中间 through_center_of: 通过 ⟺ |perp(质心−p₀)| / diag(AABB) ≤ 0.05
换的是量法不是阈值。旧量法「同侧顶点占比」是跳变的： 门铰链往里挪 1% 读数从 1.000 直接掉到 0.500，挪 50% 还是 0.500——盒子只有 8 个角， 轴线进内部就永远 4 对 4。而且排序反了：摄像机读 0.50（最差）实际只往里 3.9%； 钻床读 0.80 实际 27%。新量法注入验证线性跟踪位移，误差 < 0.005。
阈值 0.15 从硬件推：合页轴 15–25 mm、门宽 400–800 mm，往里 2–6%。不从样本挑。
range_and_reference合并
通过 ⟺ |span_model − span_declared| / span_declared ≤ state_match_relative jnt_limited[k] = 0（continuous）→ N/A
states.closed、参考构型、range.min 常是同一个数， 原方案列成三件事分别核对。同一个数算三次，正是 P0 自己禁止的重复计分。
rigid_follower补
R(b) = {b} ∪ { c : parent(c) ∈ R(b) 且 body_jntnum[c] = 0 } 通过 ⟺ b*(follower) ∈ R(b*(leader))
纯图上走一趟，抓「看一眼看不出来」的缺陷：把手螺在柜体上而不是抽屉上， 参考姿态渲染一模一样，只有拉开时才露馅。
travel_scale改
D = diag(AABB(部件自己绑定的 geom)) 通过 ⟺ D / 行程 ≥ 0.50 仅 slide
原文是「qpos 变了而可见部件不动」，而 P3 自己禁止渲染。 要抓的是：挂着关节、行程也对，但几乎没有几何。位移测不出来——假部件把 0.18 m 走完了； 能测的是尺寸：滑 0.18 m 而只有 8 mm 宽的不是抽屉。
量部件自己而非整个刚性子树——那个假部件挂了个真把手，子树 0.39 m，部件本身 0.0139 m。

Coupling Fidelity — 4 条

残差只在模型真建了约束时才存在。生成器什么都没写 → 没有残差 → 空集取 max 让判断为真 → 最差的模型得 1.0。 正文那句「检查 coupling 是否 active」是护栏，但落地的是公式。
前提：mimic 被丢掉补

不处理的话 KF2 把这 7 条全判 0，理由是「没有约束」，可它们在 URDF 里写得完全正确—— 等于让资产替读取方的缺陷背锅。（含传动比 −1 的齿轮组、14 片联动百叶窗、反向对转碎纸机。）
bound
在关节等式图上找 ind → dep 的最短链 边: q_o1 = a₀ + a₁q_o2 (a₁≠0 时含反向边) 通过 ⟺ 存在通路，且链上每条等式 active

走链而非只看直接约束：契约写 mechanism: any，声明的是关系不是实现。 手套箱把两根连杆都以 0.55 挂在门上——它们确实精确 1:1，只看直接约束会把正确机构判成缺失。
coefficient
沿链复合：斜率相乘，偏移累加 q_v = m_e(m_u·q_ind + b_u) + b_e 通过 ⟺ |ĉ−c|/|c| ≤ ε 且 |ô−o| ≤ ε 且 max|a₂..a₄| ≤ 1e−9

① C5

去掉关节约束后几何撑不撑得住。

P3 三项加起来问不到：一扇声明完美 revolute、一根合页几何都没有的门全绿—— 求解器无条件替资产执行关节约束。

② 粒度不匹配

生成器划分普遍比提示词粗：曲柄脚踏焊成一个件、灶台没有 burner link、吊扇四叶合进 rotor。

已裁定数目不一致即失败，Gate 拒掉是对的。
但吊扇值得看：23 条接触声明只评了 5 条（N/A 27 条，全场最多）， 因为点名叶片的声明都绑不上——卡住的恰好是本该起作用的那类检查。
③ P0 表达缺口

第二条已引发过一次 KF2 误判——根因是 P0 说不出那个比值。
④ range 触发 7/10
多半同一类原因：契约里那些行程数字不少是提示词没给、由契约作者填的。 需要的是逐条复核契约，不是改检查。
