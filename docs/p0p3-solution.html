00 · 总览

流水线，以及哪一段是我们的

P0 契约（人写、生成前冻结）
      │
      ├─► 准入检查 A1–A16          ✅ 本实现  契约本身能不能被检查
      │
   P1 Gate G0–G3                   ✅ 替身    资产能不能进入评分
      │
      ├──────────────┬──────────────
      ▼              ▼
 P2 GF1–GF4     P3 KF1/KF2/KF3     ✅ 本实现
 （别人的，未实现）

P2 不是 P3 的前置条件。按 spec，P2 和 P3 是并列的兄弟，两页都写着「仅评估通过 Initialization Gate 的资产」。跳过 P2 只意味着没有几何分数，不影响 P3 结论的有效性。

判分链路上有什么

全包只有三类算子：比较 87 处 · 算术 69 处 · 布尔 35 处 第三方依赖只有 mujoco / numpy / pyyaml —— 三个都跑不了模型
为什么这条能被验证而不是被承诺。 tests/test_no_model_in_the_scoring_path.py 逐模块扫 import：任何推理客户端、 HTTP 栈、socket、无种子随机源一律失败；源码逐行扫 URL 和 key 形状的字符串；依赖清单断言 只能是那三个。外加三个可复现性测试：同一输入跑三遍，准入结论、容差哈希、几何测量必须逐字节相同。

random 和推理库并列禁用是有意的——分数在两次运行之间会动，和分数取决于模型 当天的状态一样不可证伪，没人能把真实回归和噪声分开。所以 KF3 的填充层用 Halton 序列，第 k 个点 是 k 的固定函数，没有种子可设。

而且验过它抓得住：往包里塞一个 import openai 的文件，两个测试立刻红。

01 · P0

契约的每个字段：原 spec 说什么，我们改成什么，为什么

required_parts 实例枚举 替换

原 spec：{id: drawer, count: 3}，而下游用的是 drawer_1。

问题：四页 spec 里没有任何地方规定 count 怎么展开成实例，也没规定 Gate 用什么顺序 分配下标。示例里三个抽屉一模一样所以看不出来，但对左右门这类非同质的集合，实例配错就直接改变判定。

required_parts:
  - {id: drawer_1, role: movable, group: drawer}
  - {id: drawer_2, role: movable, group: drawer}
# group 是可选标签：成员是列出来的，所以 {group: drawer} 的展开确定且可校验

count 现在是加载错误，报错信息直接说明理由。

role 三值 + rigid_attachments 替换

原 spec：「fixed 或 movable」——但它自己的示例写了第三个值 role: follows_drawer。

两个毛病。那个字符串说不出哪个把手跟哪个抽屉——handle_3 跟着 drawer_2 也能全绿。更糟的是：把手若记成 movable，Gate G2 会要求它有自己的关节， 而正确的把手不应该有。
role含义Gate 的期望
fixed不动不要求运动链
movable有自己的关节恰好一条运动链
attached会动但没有自己的关节不要求关节；必须在 rigid_attachments 里出现一次
rigid_attachments:
  - {follower: handle_1, leader: drawer_1}   # 显式的实例对

axis 三种写法 替换

原 spec：axis: depth——一个词，而全篇没有任何地方定义物体坐标系。

为什么不能简单地「规定生成器按规范朝向输出」。 URDF 没有语义方向，只有数字；两个建模时差 90° 的相同柜子是同一个物体。规定朝向会把 「约定违规」变成「运动学失败」——一个完美但转了 90° 的柜子，每条轴向 claim 全错。 而我们要比的是多个生成器，那测到的就是谁读了坐标系说明，不是谁的关节做得对。这是个会直接 污染结论的混淆变量。
写法怎么判扛得住整机绕竖直轴旋转吗
semantic: vertical/horizontal对重力解析（免费）扛得住
relational: 部件间关系从两个部件的实际几何算参照扛得住
numeric: [x,y,z]直接比；front 未锚定时 N/A扛不住

宁可少测一项，也不把朝向约定的锅算到资产头上。这正是上一个项目栽过的地方—— 把读取方的不确定性当成资产的缺陷。

anchor 两条互为反面的几何谓词 替换

原 spec：散文里说声明 anchor，schema 示例里根本没有这个字段，而且示例三个关节全是 slide——恰好绕过了唯一重要的场景。

实测：把关节 pos 挪 0.25 m，子体几何位移 slide 0.000000 平移没有中心，pos 是死的 hinge 0.171449 绕过 anchor 的直线转 ball 0.191345 绕 anchor 这个点转 free 0.000000 MuJoCo 直接忽略

所以 anchor 对 hinge 和 ball 可检，对 slide 和 free 恒 N/A。 （早期版本把 ball 也排除了，是拒绝了一条模型真的能判负的声明，靠上面这组测量纠正。）

而 P0 是在资产存在之前写的，不知道门会多大、摆在哪，所以 anchor 写成几何关系而非坐标：

anchor: {on_edge_of: door}          # 门：轴线在边上
anchor: {through_center_of: gear}   # 齿轮：轴线过质心

两条必须都有，因为它们互为反面。用门的谓词去判齿轮会必然判负—— 过对称轴的任何平面都把圆盘切成两半。这个洞是写第二个金标准示例时才发现的。

couplings 与 MuJoCo polycoef 同构 补全

原 spec：couplings: []——KF2 要核的六项（成员、系数、符号、固定成员、 reference phase、expected DOF）一样都没有表示形式，整项无法实现。

couplings:
  - id: gear_mesh
    mechanism: any            # equality / tendon / weld 都接受
    relation:
      dependent:   gear_small_spin
      independent: gear_large_spin
      coefficient: -3.0       # q_dep = -3·q_ind + 0；负号因为外啮合齿轮反转
      offset:      0.0
    expected_dof:  1
    residual_norm: {by: absolute, unit: rad}
    epsilon:       0.005
为什么写成「依赖 = 系数 × 独立 + 偏移」。它逐字段对应 MuJoCo equality/joint 的 polycoef 语义 q₁ = a₀ + a₁q₂ + …， 所以比较是字段对字段，没有解释空间。但 mechanism: any——P0 声明关系， 不声明实现，生成器用固定腱做出同一个关系同样正确。
归一化量必须逐条声明。齿轮的 range 常是 ±3 圈（跨度 37.7 rad）， 相对归一化下 ε=0.02 等于容忍 0.75 rad ≈ 43° 的相位误差——对齿轮毫无意义。

asset_states 整机状态 + 容差 新增

问题：joints[].states 是每个关节自己的标签，而 contact_policy 把它当整机属性用。三个自由度扫到 (0.0, 0.40, 0.35) 时——它算不算 "closed"？

q ∈ 状态 s ⟺ ∀j ∈ scope(s): |q_j − states_j[s]| ≤ τ_rel · span_j scope = named_parts 只看声明所点名部件的关节（默认） = all_declaring 所有声明了该标签的关节

容差不是可选的。若 closed 是精确相等，连续扫掠里合格样本可能是零个， 那条声明就永远不被检查——而这会读成「通过」。

contact_policy 三桶 + 优先级 替换

原 spec：allowed / forbidden，但从未说明 allowed 断言了什么。

两种读法都致命。读作「许可」→ 它永远不会失败，对分数零贡献。 读作「义务」→ 需要接触容差和状态谓词，两个都不存在。 后果是：没有任何检查要求声明的 stop_contact 真的发生——一个只靠 range 属性限位、 全身没有几何止挡的机构，和有真止挡的得分完全一样。
contact_policy:
  required:   # 义务：该状态下必须接触，不发生即失败
    - {parts: [door, cabinet_body], state: closed, relation: stop_contact}
  permitted:  # 许可：接触不算违规，不接触也不算失败
  forbidden:  # 禁止：全行程不得穿透超阈值
    - {parts: [door, drawer_1], state: all}
  precedence: required_and_permitted_over_forbidden

优先级不是锦上添花。spec 自己的示例把同一对同时放进两个桶， S_collision 在扫掠的起点和终点上无定义。

tolerances 全部进契约 + 哈希 新增

P3 要求「所有阈值测试前冻结」，但原契约没有任何容差字段——13 个未命名阈值实际上由写代码的人默默决定。

tolerances:
  axis_angle_deg:            15.0
  anchor_edge_inset_max:     0.15
  anchor_center_offset_max:  0.05
  travel_scale_min:          0.50
  follower_drift_m:          0.0005
  state_match_relative:      0.02
  required_contact_m:        0.002
  forbidden_penetration_m:   0.001
  coupling_residual:         0.02
# tolerances.digest() → sha256 前 16 位，随每份结果输出

02 · P0

准入规则 A1–A16：契约在生成之前必须过这一关

A1 是整套规则里最重要的一条，它有实测理由。 上一轮把散文部件名去匹配代码标识符：70 次报警里 63 次误报，其中 42 次来自「找不到零件」—— 但 7 个真阳性里也有 4 个来自同一个标志。信号和噪声是同一个事件，配对 bootstrap 的 Δκ 95% CI 含零，写更好的匹配器救不了。

A1 把「契约写错」这个解释在生成之前消掉，让这个信号只剩一种含义。
规则检查为什么
A1任何字段引用的 part/joint ID 必须已声明见上
A2每个 required part 有 part_geometry沿用
A3movable 恰好一条关节声明；fixed/attached 不得有与 Gate G2 对齐
A4attached 在 rigid_attachments 里作为 follower 恰好一次否则随动件检查没输入
A5/A6independent_dofs 可解析；coupling 的 dependent 不得同时被独立驱动依赖状态由耦合算出
A7contact_policy 引用的 state 已定义否则该声明在扫掠上无法归类
A8/A9axis 至少一种形式；numeric 需 front 已锚定否则只能报 N/A
A10slide/free 的 anchor 必须 null；hinge/ball 必须给谓词平移没有作用中心
A11range.unit 与 type 相容；states 落在 range 内否则数值无法比对
A12contact 对必须两个不同部件；桶与 relation 语义相容许可不能放进义务桶
A13–A16关节不得自连；耦合成员必须也是关节声明；expected_dof 合理；free 关节警告
两层分开是有意的。loader 只回答「这个文件是不是契约的形状」， 错了就抛、带字段路径；admission 回答「这个格式正确的契约能不能被检查」， 返回报告——因为可以同时有好几条，而且读的人是要去改 YAML 的人。

每条规则都有一个测试，只破坏金标准契约的一处，断言它被触发。触发不了的规则等于没有。

03 · 共用机制

三件所有谓词都用的东西

绑定 b*(P)

Gate 给出 part id → body id。P3 只读，绝不推断名字。一个部件常是多个 body（抽屉是底板加四面墙）， b*(P) 取其中在树上作为其余祖先的那个。

参考位姿 q_ref

q_ref[j] = states_j["closed"] 若存在，否则 states_j["home"]，否则 range_j.min 所有几何类 KF1 谓词都在这一个冻结位姿上读数

这样两条谓词不一致时，那是对声明的分歧，不是对「当时资产站在哪」的分歧。

点云 P(part)

盒子取 8 个角点（精确）；其余图元和网格取其局部 AABB 的角点——保守方向：只会让部件显得更大， 绝不会更小，所以不会因为采样漏掉了部件的一部分而误判它「全在一侧」。

rot = geom_xmat[g].reshape(3,3);  origin = geom_xpos[g]
box:   local = 8 corners × geom_size[g]
其他:  local = geom_aabb[g][:3] + 8 corners × geom_aabb[g][3:]
world = origin + local @ rot.T

距离：为什么不读 mjData.contact

实测：546 条真实资产里零个有 <collision>。 所有 geom 编译出来 contype = conaffinity = 0，MuJoCo 的宽相位全部跳过， mjData.ncon 恒为 0。基于接触的碰撞检测在这里什么都返回不了。

所以一律走 mj_geomDistance。它不看 contype/conaffinity， 也不受父子过滤影响——而后者才是关键：MuJoCo 默认关掉有关节相连的父子碰撞， 那正是扫掠干涉检查最需要看的那一对（门 vs 自己的门框、抽屉 vs 自己的柜体）。

04 · KF1

关节配置保真度：9 条谓词

KF1.parent 父件 照做

命题：这个关节让部件相对 P0 指定的那个部件运动。

A(b) = 从 b 沿 body_parentid 上溯遇到的第一个已绑定部件 PASS ⟺ A(b*(part)) = parent
observed, steps = binding.nearest_declared_ancestor(child)
verdict = PASS if observed == joint.parent else FAIL
为什么是「最近的已声明祖先」而不是「是不是祖先」。 挂在上层抽屉下的下层抽屉，柜体仍然在它的祖先链上——问「声明的父件在不在上面」会放它过去， 而那正是「拉开上抽屉会把下抽屉一起拖出来」的缺陷。

未声明的中间 body 透明：生成器会自由插入无名连杆，把它当父件会因为一种契约根本没提的 建模风格判负正确资产。

反例：wrong_parent——drawer_2 挂到 drawer_1 上，只改 body_parentid 一个字段。

KF1.type 关节类型 照做

μ: slide↦mjJNT_SLIDE, hinge↦mjJNT_HINGE, ball↦mjJNT_BALL, free↦mjJNT_FREE PASS ⟺ jnt_type[k] = μ(declared)

本组最弱的一条，明说。上一轮语料里关节类型解析完整率 100%、几乎总是匹配， 而且有 6 条记录声明的类型与提示词逐字相同、人类照样判失败。保留是因为它便宜且失败无歧义， 但它被归进「读字段」子分数单独报，不和测量类混在一起稀释后者。

KF1.dof_composition 自由度构成 替换 spec 的第 4 条

PASS ⟺ body_jntnum[b*(part)] = 1
原 spec 的第 4 条两半都是恒真式。 「slide 不得产生额外旋转」——MuJoCo 的 slide 按定义是纯平移。 「hinge 的 anchor 在小扰动下保持固定」——mj_kinematics 就是按声明的 jnt_pos 算出锚点的。 没有任何模型能让它们失败。

但它们瞄准的失败是真的：一个部件被挂了 free 关节、或用 slide+hinge 复合假装单自由度， 它的运动方式就不是那一个声明自由度所描述的。数关节个数是模型真的能失败的检查；问 slide 转不转不是。

KF1.axis_semantic 轴向（语义） 照做

û = −g / |g| g = model.opt.gravity（默认 (0,0,−9.81)） â = xaxis[k] / |xaxis[k]| 世界系，mj_forward 之后直接可读 c = |â · û| vertical: PASS ⟺ c ≥ cos(τ) horizontal: PASS ⟺ c ≤ sin(τ) τ = axis_angle_deg = 15°

唯一不需要物体坐标系的方向判定，而且绕竖直轴旋转整机不改变它—— 一个转了 90° 的正确柜子不会因此判负。它明说自己看不见更细的方向：抽屉往侧面滑和往外滑一样是水平的。

KF1.axis_admits_motion 轴向（几何可行） 新增

更细的方向唯一的无参照系证据：往这个方向走得通吗。

d₀ = min signed distance(part, parent) at q_ref 若 d₀ < −ε: N/A ← 静态互穿门控 部件已经埋在父件里时，「往哪个方向动会不会干涉」没有意义——每个方向都会。 那是静态几何的账。 δ = min(0.25 · span, 0.05) q ← q_ref + δ·(声明轴向) ; mj_forward d₁ = min signed distance(part, parent) PASS ⟺ d₁ ≥ −ε ε = forbidden_penetration_m

反例：axis_rotated_90——抽屉往侧面滑，撞进左墙。axis_semantic 看不见它，这条抓住。

KF1.anchor 锚点 替换

on_edge_of（门、盖、翻板）

p₀ = xanchor[k], â = xaxis[k]/|xaxis[k]| r_i = (p_i − p₀) − ((p_i − p₀)·â) â 去掉沿轴分量 d = r̄/|r̄|（质心径向）；|r̄|≈0 时取 {r_i} 的第一主成分并去掉沿轴分量 s_i = r_i · d inset = min(|min s|, |max s|) / (max s − min s) PASS ⟺ inset ≤ anchor_edge_inset_max = 0.15 0 = 轴线正好在边上 0.5 = 轴线在正中间
这条被换过一次，而且换的是「测量」而不是「阈值」。 最初的测量是「同侧顶点占比 ≥ 0.95」。注入校准发现它是阶跃函数： 把已知正确的门铰链往里挪 1%，读数从 1.000 直接掉到 0.500；挪 2%、5%、50% 全都是 0.500。 一个盒子只有 8 个角点，轴线一旦在内部就永远 4 对 4。真实资产读到的 0.69/0.75/0.83/0.91 只反映几何被拆成了几个 geom，不反映轴线在哪。

更糟：它把排序弄反了。摄像机门读 0.50（全场最差）实际内嵌只有 3.9%，是最干净的铰链； 钻床工作台读 0.80（看起来还行）实际内嵌 27%，是真问题——而人工正是判钻床「轴向」失败、 没判摄像机。旧测量在两个方向上同时和人工相反。

新测量注入验证线性跟踪位移，误差 < 0.005，且与细分方式无关。 阈值 0.15 从硬件推：合页轴 15–25 mm、门宽 400–800 mm，内嵌 2–6%，所以 15% 已宽松、25% 肉眼就不是边缘铰链。 不从样本推——那是拿仪器迁就样本。

through_center_of（轮、齿轮、旋钮）

offset = |perp(centroid(P) − p₀)| PASS ⟺ offset / diag(AABB(part)) ≤ anchor_center_offset_max = 0.05

归一化用部件自身的对角线，绝不用整机对角线——上一轮 607 条里只有 19 条能算出整机对角线。

KF1.range_and_reference 行程与参考 合并

span_model = jnt_range[k][1] − jnt_range[k][0] PASS ⟺ |span_model − span_declared| / span_declared ≤ state_match_relative jnt_limited[k] = 0（URDF 的 continuous）→ N/A

一条 claim，不是四条。states.closed、参考构型、range.min 通常是同一个数，而 spec 把它们列成三件要分别核对的事。同一个数算三次就是 P0 自己那条 「同一信息不重复计算」所禁止的重复计分。

KF1.rigid_follower 刚性随动 新增

R(b) = {b} ∪ { c : parent(c) ∈ R(b) ∧ body_jntnum[c] = 0 } 不跨越任何关节可达 PASS ⟺ b*(follower) ∈ R(b*(leader))

纯图运算，零成本，而且抓的是一个「看一眼看不出来」的缺陷： 把手螺在柜体上而不是抽屉上，参考位姿下渲染出来一模一样，只有抽屉拉开时才露馅。 在一个构型上评估的检查看不见它，图上走一趟就能。

KF1.travel_scale 假关节 替换 spec 的「可见部件不动」

D = diag(AABB(该部件自身绑定的 geom)) PASS ⟺ D / travel ≥ travel_scale_min = 0.50 仅 slide
原 spec：「不出现 qpos 改变而可见部件不动」—— 「可见」需要渲染，而 P3 自己的 Scope 禁止渲染。 它点名了人类最容易说出口的运动学失败（「我拉开了，什么都没动」），却没有可用的算子。

要抓的是：body 挂着声明的关节和正确的行程，却几乎没有几何，看得见的抽屉是静止体的 geom。 位移测不出来——诱饵桩子走完了全程 0.18 m。能测出来的是尺寸。滑 0.18 m 而只有 8 mm 宽的东西，不是抽屉。

归一化用关节自己声明的行程，不用整机对角线。

量的是「部件自身」而不是「它带动的一切」——诱饵桩子上挂着一个真的 0.16 m 把手，刚性子树 0.39 m 宽，而契约点名的部件只有 0.0139 m。

05 · KF2

机械耦合保真度：4 条谓词

先说公式为什么必须改。 原式 KF2 = mean_g 1[max_q |r| ≤ ε] 读的是残差， 而残差只在模型实例化了约束对象时才存在。生成器什么都没写 → 没有残差 → 空集取 max 使指示函数为真 → 最差的模型得 1.0。

散文 bullet「检查 coupling 是否 active」本是护栏，但落地的是公式。
KF2 = mean_g 1[bound(g)] · 1[ max_q |r_g,norm(q)| ≤ ε_g ]

前置：URDF 的 <mimic> 被 MuJoCo 静默丢弃

实测：7 条真实资产声明了 <mimic>，加载后 neq 全是 0。 其中有 −1 和 0.777778 传动比的齿轮组、14 片联动的百叶窗、两台反向对转刀盘的碎纸机。 不管的话 KF2 会把这 7 条全判 0——理由是「没有实现耦合的约束」，可它们在 URDF 里声明得完全正确。 那是在替读取方的缺陷怪资产。

两条 XML 路都不通（URDF 里的 <mujoco><equality> 被忽略； mj_saveLastXML round-trip 丢几何），所以在编译前编辑 MjSpec。 URDF 的 q_dep = k·q_ind + c 与 polycoef 逐字段对应，翻译没有解释空间。 每一次翻译都记进 provenance。

KF2.bound

E(g) = { e : eq_type[e] = mjEQ_JOINT ∧ {eq_obj1id[e], eq_obj2id[e]} = {dep, ind} } PASS ⟺ ∃ e ∈ E(g), eq_active0[e]

它绝不从「两个关节碰巧一起动」推出耦合。没有东西强制的关系不是关系，不管某个构型下数字多好看。

KF2.coefficient

MuJoCo: q_{obj1} = a₀ + a₁·q_{obj2} + a₂q² + a₃q³ + a₄q⁴ obj1 = dep: ĉ = a₁, ô = a₀ obj1 = ind: ĉ = 1/a₁, ô = −a₀/a₁ 角色互换 —— 同一个机构，不判负 PASS ⟺ |ĉ−c|/|c| ≤ ε ∧ |ô−o| ≤ ε ∧ max|a₂..a₄| ≤ 1e−9

符号是比值的一部分，不是约定。外啮合齿轮反向转，所以声明 −3 而建成 +3 描述的是一个造不出来的机构，这条会点名它是「符号反了」而不是报一个百分比。

KF2.expected_dof

n = Σ_{j∈members} dof(jnt_type[j]) free=6, ball=3, slide=1, hinge=1 m = #{ e : eq_type=JOINT ∧ active ∧ {obj1,obj2} ⊆ members } PASS ⟺ n − m = expected_dof

它把「互相约束」和「碰巧一起动」分开。两个 hinge 加一条关节等式剩 1 个自由度。 （数行数而非取 efc_J 的秩，假设这些行独立——单条等式必然成立；两条冗余等式会被高估， 记为局限而不是掩盖，而语料里不出现，因为耦合来自 <mimic> 且 MuJoCo 每关节只允许一条。）

它和 bound 从两个独立方向抓同一个缺陷：bound 读模型的约束表， expected_dof 数还剩几个自由度。骗过一个的模型得用另一种方式去骗第二个。

KF2.residual

for q in linspace(range.min, range.max, 33): 端点含、奇数含中点 qpos[ind] ← q qpos[dep] ← c·q + o ← 把模型摆到「目标流形」上 mj_forward(m, d) ← 位置级，不步进，无质量/摩擦/阻尼 rows = { i : efc_type[i]=EQUALITY ∧ efc_id[i]=e } r(q) = max |efc_pos[rows]| R = max_q r(q) / N N ∈ {dependent_range_span, independent_range_span, absolute} PASS ⟺ R ≤ ε_g

实测（金标准齿轮箱）：

构型max |efc_pos|含义
正确 −30.000000两种描述完全一致
建成 −26.283输入转一圈，输出差一圈
建成 +337.698差六圈——符号错比齿比错更荒谬，读数也确实更大
无约束N/A由 bound 判负，不由这条报「齿比错了」

没有约束时 coefficient 和 residual 弃权而不判负。 对一个根本不存在的关系报「齿比错了」是点错了缺陷的名字——缺失是 bound 的账。

06 · KF3

四层扫掠：确定性、可负担、可审计

原 spec 只写了「确定性 feasible q-sweep」，没有任何采样规则。示例资产 3 个自由度， 满网格 33³ = 35,937 个构型，而且随自由度指数增长（6 个自由度 = 13 亿）。 逐自由度单独扫很便宜，但对「两个抽屉同时拉开才会撞」完全失明。

层内容买到了什么柜子成本
参考q_ref基线1
① 逐自由度每关节 33 点，其余在参考态单一运动撞到的东西——绝大多数99
② 成对网格9×9，只对扫掠包围盒可能相交的对交互失败243
③ 状态组合声明的语义状态全部 2^d（d>12 封顶）人类真正命名的构型，精确访问8
④ Halton 填充256·d 点结构化日程会跨过去的东西768
合计1,119

② 的邻接判据——它才是「可负担」的来源

B(j) = ⋃_{v ∈ {lo, (lo+hi)/2, hi}} AABB_conservative( subtree(child(j)) at q_j=v ) pad = 0.05 · max( diag B(a), diag B(b) ) 若 B(a) 与 B(b) 膨胀 pad 后仍不相交 → 跳过这一对，并记进报告

用保守包围盒（bounding sphere 半径）是有意的方向：高估的代价是白扫一对， 低估的代价是漏掉这一层存在的理由。跳过了哪些对写进 pairs_skipped—— 静默截断读起来和覆盖全了一模一样。

④ Halton，而不是 Sobol，更不是随机

φ_b(k) = Σ_{i≥0} d_i(k) · b^(−i−1) d_i(k) = k 在 b 进制下第 i 位 第 k 个点的第 j 维 = φ_{p_j}(k) p = (2,3,5,7,11,13,…)

没有种子可设，因为什么都没抽——第 k 个点是 k 的固定函数。 分数在两次运行之间会动，任何回归都和噪声分不开。 （Halton 在十维以上相关性变差，所以它是补充结构化层，不独自承担覆盖。这条记在代码里。）

扫掠区间取契约的还是模型的

取契约声明的 range，不取模型的。模型 range 写错是 KF1 的账； 用模型的区间会把搜索悄悄缩到资产恰好允许的范围——一个把行程写小的资产会因此被扫得更松。

依赖自由度

每个样本上，依赖关节由契约的耦合关系算出，不由模型的约束算出。 这正是扫掠的意义：把模型摆到 P0 说它该在的地方，它自己的机构在那里同不同意，是 KF2 的残差。

07 · KF3

可行运动一致性：3 条谓词

先说 spec 的「运动有效性」为什么大部分被替换。 「closed/open/中间状态可达」「轨迹连续」「相对位姿遵循关节语义」—— 在编译好的 mjModel 上全是正向运动学的性质，而 FK 按构造精确且连续。 把构型写进 qpos 永远成功。没有资产能让它们失败。

能失败的是到达那里的路上撞不撞自己，所以「可达」被重写成 「在不产生禁止干涉的前提下可达」——那是关于资产的问题。

KF3.forbidden_pair 禁止对

Q = 扫掠样本集 exempt(q, pair) = ∃ required/permitted 声明，同一对，且 q 属于它声明的状态 pen(q) = max(0, −min signed distance(a, b) at q) 该对 PASS ⟺ max_{q ∈ Q, ¬exempt} pen(q) ≤ forbidden_penetration_m S_forbidden = 通过的禁止对数 / 可解析的禁止对数 可解析对数 = 0 → N/A，不是 1.0
逐对计分，不是逐样本。一千个构型里有一个深度互穿，那是一个坏掉的对。 除以样本数会读成 0.99997——同一个缺陷会随扫掠精度移动四个数量级。 构型是证据（报 first failing q），不是分母。

反例 swept_interference：门的弧线里放一个支架。

门开角 与柜体最小间距 0° +0.00000 20° +0.00000 25° −0.00509 ✗ 30° −0.02791 ✗ 35° −0.01119 ✗ 40° +0.00000 90° +0.00000 两个端点都干净，只在中间撞。任何只在声明状态上检查的方法都会判它完美。

KF3.required_contact 义务接触

Q_s = { q ∈ Q : q 属于状态 s } PASS ⟺ min_{q ∈ Q_s} d(a, b) ≤ required_contact_m Q_s = ∅ → N/A（从未被评估的声明不是被满足的声明）

这是旧 allowed 桶里那半「永远不会失败」的东西。 作为义务，它抓的是只靠 range 属性限位、全身没有几何止挡的机构—— 那是「机构」和「声明」的区别。金标准的柜子本来就有这个毛病，加了前挡边才修好。

KF3.state_reachability 状态可达

PASS ⟺ max_{q ∈ Q_s} max_{forbidden pairs, ¬exempt} pen(q) ≤ forbidden_penetration_m

不是「状态可不可达」——那是采样器的性质，不可能失败。 是「能不能干净地保持在那个状态」。

08 · 聚合与报告

让判定可以被质疑

score(R) = |{ r ∈ R : verdict = PASS }| / |{ r ∈ R : verdict ≠ N/A }| 分母 = 0 → None，不是 1.0，也不是 0.0

两个极端都是在为一个没人测过的维度发明结果。 空分母的指标不是「测到了一个完美的资产」，是「什么都没测到」。

三态而不是两态

PASS / FAIL / N/A。N/A 存在是因为另一种做法更糟： 工具无法评估的声明记成通过，和它评估过并判定满足，完全无法区分。 上一个项目把读不出的字段当成缺失的字段，把读取方的缺口算到了资产头上。

报告拒绝三种会误导人的形状——不是记录，是拒绝写出去

拒绝为什么
判负但没写理由无法被质疑的判定是断言，不是证据
有结论但没有测量值同上
弃权但没说读不到什么扫表格的人分不清没写理由的 N/A 和 pass

每份报告必带出处与覆盖

provenance: {inertia_synthesized, mimics_translated, distance_backend, notes}
coverage:   {samples, by_layer, pairs_swept, pairs_skipped, scan_points, …}
tolerance_digest: sha256[:16]

出处：没人应该靠信任来相信合成的惯量和恢复的耦合没进分数。 覆盖：静默跳过一半构型空间的日程，读起来和覆盖全了的一模一样。

KF1 按「怎么判出来的」分开报

KF1.declared = score(读字段类: type, range_and_reference) KF1.measured = score(其余全部)

上一轮语料里读字段类几乎全通过，混在一起会把真正会变的那些淹掉。 实测：range_too_small 上 declared=0.83 / measured=1.00， hinge_through_middle 上正好反过来。

09 · 验证

13 份金标准资产：缺陷是我们造的，答案已知

为什么必须有它们。拿真实资产跑，输出 0.87——这个数对不对没人知道。 而最糟的是恒真式：它在所有资产上输出「通过」，看起来像「资产都挺好」，不像「代码坏了」。 真实资产本来大部分就是通过的，两者长得一模一样。恒真式在没有已知坏输入的情况下是隐形的。
资产 KF1 KF3 诊断 cabinet_correct 1.00 1.00 — wrong_parent 0.96 1.00 KF1.parent wrong_joint_type 0.91 0.89 KF1.type + range（单位随类型变） hinge_through_middle 0.96 1.00 KF1.anchor axis_rotated_90 0.96 1.00 KF1.axis_admits_motion range_too_small 0.96 1.00 KF1.range_and_reference detached_follower 0.96 1.00 KF1.rigid_follower fake_joint_decoy_geom 0.95 1.00 KF1.travel_scale door_axis_horizontal 0.91 0.89 KF1.axis_semantic + anchor swept_interference 1.00 0.89 KF3.forbidden_pair gearbox_correct KF2=1.00 — gearbox_wrong_ratio KF2=0.50 KF2.coefficient + residual gearbox_wrong_sign KF2=0.50 同上（符号反） gearbox_missing_coupling KF2=0.00 KF2.bound + expected_dof ← 原公式给 1.00

每条谓词过三关，不是两关：正确件上不响 · 自己的反例上响 · 别人的反例上也不响。 第三关是「谓词」和「烟雾报警器」的分界——什么坏了都响的检查没有诊断出父子错，只诊断出「有东西不一样」。

反例存成对正确件的最小编辑（120 条逐谓词预期写在 manifest 里）， 所以缺陷是可读的 diff，而且改不动正确件而不被发现。匹配不到任何东西的替换直接报错—— 否则「反例」就和对照件一模一样，拿它测出来的谓词看着可靠、实际什么都没查。

光是把正确件建出来，就当场抓到 5 个 bug（真实资产一个都发现不了）： loader 用子串搜 <inertial 而注释里正好写了这几个字；subtree_aabb 用包围球高估了一个半对角线； 门轴绕 +z 转导致往柜子里面开、互穿 0.040 m；门把手埋在自己门板里； 以及——控制件本身有一个「只靠 range 限位、没有几何挡住门」的问题，正是 required_contact 要抓的那类失败。

10 · 诚实边界

还没解决的四件事

① C5：把关节约束拿掉，几何撑不撑得住

P3 的三项加起来都问不到这个问题。一扇声明了完美 revolute 关节、 一根合页几何都没有的门，KF1/KF2/KF3 全绿——求解器无条件替资产执行关节约束。

而这在人工标注里是失败最多的一项：425 条里 103 条，比第二名多十倍。 试点已在真实资产上证实：rec_stove_top_0002 P3 每一项 1.00、零失败，人工单独在这一项判不满足。

我们建的东西里有它的两块碎片（travel_scale、required_contact）， 但都不问它的核心问题。已按你的决定推迟，做的时候作为独立命名的扩展项、不进 Kinematic Profile， 两张表并排报。

② 部件粒度不匹配

10 个真实资产里，生成器的部件划分普遍比提示词粗：曲柄脚踏把主轴+两臂+链轮焊成一个 crank_assembly；灶台没有任何 burner link；吊扇把四个叶片合并进 rotor。

已裁定：数目和提示词不一致即失败，G1 拒掉它们是正确行为。 这条裁定还消掉了一个误报——曲柄脚踏的「父子错」是绑定有损造成的，人工判它全部满足， 而在这条裁定下它根本到不了 P3。

但吊扇那条值得单看：人工判它穿模，那正是 KF3 的本职， 而 KF3 只评了 23 条接触声明里的 5 条，因为每一条点名叶片的声明都绑不上。 粒度问题卡住的，正是那条本来会和人工一致的检查。

③ P0 的两个表达缺口

缺口在哪暴露
无界复数：删掉 count 后无法表达「若干个键」 笔记本资产有 48 个独立按键 link，契约一个都没声明 → 48 个真实自由度无人评估
几何决定的比值：无法表达「这些联动，比值由几何定而非声明」 手套箱门的四连杆——门与限位连杆的比值提示词没给，只能声明「双连杆彼此 1:1」

④ KF1.range_and_reference 触发率 7/10，可疑

多半是同一类问题：我写契约时那些行程数字，很多是提示词没给、我自己填的 （笔记本的 2.1 rad 就在契约注释里写明了是作者判断）。这需要的是契约复核，不是改谓词。

还有一条一直存在的、只能靠人解决的：契约由谁写。 判分链路是纯数学没错，但契约本身是写出来的文本。哈希冻结防的是「看了资产再改契约」， 防不了「一开始就读错提示词」——钻床那条我把「locking features」读成 1 个锁柄，资产有 2 个， 那是契约作者的错。所以流程必须是：起草 → 逐条签字 → 再冻结。
