判分过程里有什么

全包只有三类运算：比较 87 处 · 加减乘除 69 处 · 逻辑判断 35 处 第三方库只有 mujoco / numpy / pyyaml —— 三个都跑不了模型
这一条是能验证的，不是口头保证。 tests/test_no_model_in_the_scoring_path.py 逐个模块扫 import：任何模型客户端、 网络请求、socket、没有固定顺序的随机源一律判失败；再断言依赖清单只能是那三个； 另有三个可复现测试，同一份输入连跑三遍，结论和测量必须一个字节都不差。

把 random 和模型库放在一起禁用是有意的——分数在两次运行之间会变， 和分数取决于模型当天状态一样没法追究。所以 KF3 的填充层用 Halton 序列，没有种子可设。

这套守卫验过管用：塞一个 import openai 的文件进去，两个测试立刻红。

01 · P0

契约的每个字段：原方案怎么写的，改成了什么

required_parts 逐个列实例 替换

原方案：{id: drawer, count: 3}，而下游用的是 drawer_1。

问题：方案里没有一处规定 count 怎么展开成实例。示例里三个抽屉一模一样所以看不出来， 但对左右门这种不一样的集合，实例配错就直接改变判定。

required_parts:
  - {id: drawer_1, role: movable, group: drawer}
  - {id: drawer_2, role: movable, group: drawer}
# group 只是个可选标签：成员是明写的，所以 {group: drawer} 怎么展开是确定的

count 现在直接报加载错误，错误信息里说明理由。

role 三个取值 + rigid_attachments 替换

原方案：「fixed 或 movable」——但它自己的示例里出现了第三个值 role: follows_drawer。

两个毛病：那个字符串说不清哪个把手跟着哪个抽屉（handle_3 跟着 drawer_2 也能全绿）； 而且把手要是记成 movable，Gate 会要求它有自己的关节，可正确的把手不该有。
role含义Gate 的期望
fixed不动不要求关节
movable有自己的关节恰好一条
attached会动，但没有自己的关节不要求关节；必须在 rigid_attachments 里出现一次
rigid_attachments:
  - {follower: handle_1, leader: drawer_1}   # 明确到实例

axis 三种写法 替换

原方案：axis: depth——一个词，而全篇没有任何地方定义物体坐标系。

为什么不能简单地要求「生成器按规定朝向输出」。 URDF 里没有语义方向，只有数字；两个建模时差 90° 的相同柜子是同一个物体。规定朝向会把 「没按约定摆」变成「运动学做错了」——一个完全正确但转了 90° 的柜子每条轴向判定全错。 用来比较多个生成器时，测到的就成了谁读了坐标系说明，不是谁的关节做得对。
写法怎么判整机绕竖直轴转一下还成立吗
semantic：vertical / horizontal对重力算夹角（不花钱）成立
relational：部件之间的关系从两个部件的实际几何算参照成立
numeric：[x,y,z]直接比；没锚定 front 时记 N/A不成立

宁可少测一项，也不把朝向约定的锅算到资产头上。上一个项目正是栽在这里—— 把读取方的不确定当成了资产的缺陷。

anchor 两条相反的几何判定 替换

原方案：正文里说要声明 anchor，但 schema 示例里根本没有这个字段，而且示例三个关节全是 slide——恰好绕开了唯一重要的场景。

实测：把关节 pos 挪 0.25 m，子部件几何位移多少 slide 0.000000 平移没有中心，pos 不起作用 hinge 0.171449 绕过 anchor 的那条直线转 ball 0.191345 绕 anchor 这个点转 free 0.000000 MuJoCo 直接忽略

所以 anchor 对 hinge 和 ball 可检，对 slide 和 free 一律 N/A。 （早期版本把 ball 也排除在外，等于拒绝了一条模型真的能做错的声明，靠上面这组实测纠正。）

P0 是在资产存在之前写的，不知道门会多大、摆在哪，所以 anchor 写成几何关系而不是坐标：

anchor: {on_edge_of: door}          # 门：轴线在边上
anchor: {through_center_of: gear}   # 齿轮：轴线过中心

两条必须都有，因为它们互为相反。拿门的那条去判齿轮会必然判负—— 过对称轴的任何一个平面都把圆盘切成一半一半。这个洞是写第二个标准资产时才发现的。

couplings 与 MuJoCo 的 polycoef 一一对应 补全

原方案：couplings: []——KF2 要核的六项（成员、系数、符号、固定成员、参考相位、 剩余自由度）一样都没有写法，整项没法实现。

couplings:
  - id: gear_mesh
    mechanism: any            # equality / tendon / weld 都接受
    relation:
      dependent:   gear_small_spin
      independent: gear_large_spin
      coefficient: -3.0       # q_小 = -3 × q_大 + 0；负号是因为外啮合齿轮反着转
      offset:      0.0
    expected_dof:  1
    residual_norm: {by: absolute, unit: rad}
    epsilon:       0.005
为什么写成「依赖 = 系数 × 独立 + 偏移」。它逐字段对上 MuJoCo equality/joint 的 q₁ = a₀ + a₁q₂ + …，所以比较是字段对字段， 没有解释余地。但 mechanism: any——P0 声明的是关系，不是实现方式， 生成器用固定腱做出同一个关系同样正确。

归一化方式必须逐条声明。齿轮的行程常是 ±3 圈（跨度 37.7 rad）， 按相对值算的话 ε=0.02 等于容忍 0.75 rad ≈ 43° 的相位误差，对齿轮毫无意义。

asset_states 整机状态 + 容差 新增

问题：joints[].states 是每个关节自己的标签，而 contact_policy 把它当成整机的属性用。三个自由度采样到 (0.0, 0.40, 0.35) 时——它算不算 "closed"？

q 属于状态 s ⟺ 对 scope 里的每个关节 j: |q_j − states_j[s]| ≤ τ_rel × span_j scope = named_parts 只看被声明点名的部件的关节（默认） = all_declaring 所有声明了这个标签的关节

容差不能省。如果 closed 要求精确相等，连续采样里合格的样本可能一个都没有， 那条声明就永远不被检查——而这会被读成「通过」。

contact_policy 三个桶 + 优先级 替换

原方案：allowed / forbidden，但从没说过 allowed 到底在声明什么。

两种读法都是坏的。当成「允许」→ 它永远不会失败，对分数没有任何贡献。 当成「必须」→ 需要接触容差和状态判定，这两样都不存在。 结果是：没有任何检查要求声明的止挡真的发生过——一个只靠 range 属性限位、 全身没有任何几何挡住的机构，和有真止挡的得分完全一样。
contact_policy:
  required:   # 必须：这个状态下要接触，不接触就算失败
    - {parts: [door, cabinet_body], state: closed, relation: stop_contact}
  permitted:  # 允许：接触不算违规，不接触也不算失败
  forbidden:  # 禁止：全程不得穿模超过阈值
    - {parts: [door, drawer_1], state: all}
  precedence: required_and_permitted_over_forbidden

优先级不是可有可无的。原方案自己的示例就把同一对同时放进了两个桶， 结果是 S_collision 在采样的起点和终点上没有定义。

tolerances 全部写进契约并哈希 新增

P3 要求「所有阈值在测试前冻结」，但原契约一个容差字段都没有，13 个没名字的阈值实际上由写代码的人默默决定。

tolerances:
  axis_angle_deg:            15.0     anchor_edge_inset_max:     0.15
  anchor_center_offset_max:  0.05     travel_scale_min:          0.50
  follower_drift_m:          0.0005   state_match_relative:      0.02
  required_contact_m:        0.002    forbidden_penetration_m:   0.001
  coupling_residual:         0.02
# tolerances.digest() → sha256 前 16 位，跟着每份结果一起输出

02 · P0

准入规则 A1–A16：契约在生成之前必须先过这一关

A1 是最重要的一条，而且有实测依据。 上一轮用文字部件名去匹配代码里的标识符：70 次报警里 63 次是误报，其中 42 次是「找不到零件」—— 但 7 个真问题里也有 4 个来自同一个信号。有用的和没用的是同一件事，配对 bootstrap 算出的 Δκ 95% 区间包含零，写个更好的匹配器救不了。

A1 的作用是把「契约写错了」这个可能性在生成之前消掉，让这个信号只剩一种含义。
规则检查什么为什么
A1任何字段引用的部件/关节 ID 必须已声明见上
A2每个必需部件都有 part_geometry沿用
A3movable 恰好一条关节声明；fixed / attached 不能有与 Gate 对齐
A4attached 在 rigid_attachments 里作为 follower 恰好出现一次否则随动检查没有输入
A5 / A6independent_dofs 能解析；耦合的 dependent 不能同时被独立驱动依赖端的值由耦合算出
A7contact_policy 引用的 state 已定义否则那条声明在采样上归不了类
A8 / A9axis 至少给一种写法；numeric 需要已锚定 front否则只能记 N/A
A10slide / free 的 anchor 必须为空；hinge / ball 必须给判定方式平移没有作用中心
A11range.unit 与 type 相配；states 落在 range 里否则数值没法比
A12接触对必须是两个不同部件；桶和 relation 语义相配「允许」不能放进「必须」桶
A13–A16关节不能自己连自己；耦合成员必须也是关节声明；expected_dof 合理；free 关节给警告
分成两层是有意的。loader 只回答「这个文件是不是契约的形状」， 错了就抛异常并给出字段路径；admission 回答「格式正确的契约能不能被检查」，返回一份报告—— 因为可能同时有好几条。每条规则都配一个测试，只破坏标准契约的一处，断言它被触发。触发不了的规则等于没写。

03 · 共用机制

三件所有检查都要用的东西

绑定 b*(P)

Gate 给出「部件 ID → body ID」。P3 只读，绝不自己猜名字。一个部件常常是好几个 body （抽屉是底板加四面墙），b*(P) 取其中在树上是其余那些的祖先的那个。

参考姿态 q_ref

q_ref[j] = states_j["closed"]，没有就用 "home"，再没有就用 range_j.min 所有跟几何有关的 KF1 检查都在这一个固定姿态上读数

这样，两条检查结论不一致时，那是对声明本身的分歧，不是对「当时资产站在哪」的分歧。

取点 P(part)

盒子取 8 个角（精确）；其他图元和网格取它局部包围盒的 8 个角——方向是往大了取： 只会让部件显得更大，不会更小，所以不会因为取点漏掉了部件的一部分而误判它「全在一侧」。

rot = geom_xmat[g].reshape(3,3);  origin = geom_xpos[g]
box:   local = 8 个角 × geom_size[g]
其他:  local = geom_aabb[g][:3] + 8 个角 × geom_aabb[g][3:]
world = origin + local @ rot.T

距离：为什么不读 mjData.contact

实测：546 条真实资产里，有 <collision> 的是零个。 所有 geom 编译出来 contype = conaffinity = 0，mjData.ncon 永远是 0， 基于接触点的碰撞检测在这里什么都返回不了。

所以一律用 mj_geomDistance。它不看 contype / conaffinity， 也不受父子过滤影响——后者才是关键：MuJoCo 默认关掉有关节相连的父子碰撞， 而那恰好是采样时最需要看的一对（门 vs 自己的柜体）。

04 · KF1

关节配置保真度：9 条检查

KF1.parent 父件 照做

要判的：这个关节让部件相对 P0 指定的那个部件运动。

A(b) = 从 b 沿 body_parentid 往上找，遇到的第一个已绑定部件 通过 ⟺ A(b*(part)) = parent
observed, steps = binding.nearest_declared_ancestor(child)
verdict = PASS if observed == joint.parent else FAIL
为什么要「最近的已声明祖先」而不是「是不是祖先」。 挂在上层抽屉下面的下层抽屉，柜体仍然在它的祖先链上——问「声明的父件在不在上面」会放它过去， 而那正好是「拉开上抽屉会把下抽屉一起拖出来」这个缺陷。

没声明的中间 body 直接跳过：生成器会自由插入没名字的连杆，把它当父件会因为一种 契约根本没提的建模习惯，判负正确的资产。

反例：wrong_parent——drawer_2 挂到 drawer_1 上，只改 body_parentid 一个字段。

KF1.type 关节类型 照做

μ: slide↦mjJNT_SLIDE, hinge↦mjJNT_HINGE, ball↦mjJNT_BALL, free↦mjJNT_FREE 通过 ⟺ jnt_type[k] = μ(声明的类型)

这组里最弱的一条，明说。上一轮语料里关节类型几乎总是对得上，而且 有 6 条记录声明的类型和提示词一字不差、人还是判了失败。留着是因为它便宜、失败时没有歧义， 但它归进「读字段」子分数单独报，不和测量类混在一起把后者冲淡。

KF1.dof_composition 自由度构成 替换原第 4 条

通过 ⟺ body_jntnum[b*(part)] = 1
原方案的第 4 条两半都是永远不会失败的检查。 「slide 不得产生额外旋转」——MuJoCo 的 slide 按定义就是纯平移；「hinge 的 anchor 在小扰动下保持固定」—— mj_kinematics 就是按声明的 jnt_pos 算出锚点的。没有任何模型能让这两句失败。

但它们想抓的失败是真的：一个部件挂了 free 关节、或用 slide+hinge 组合假装单自由度， 运动方式就不是那一个声明的自由度所描述的。数关节个数是模型真的能做错的检查；问 slide 转不转不是。

KF1.axis_semantic 轴向（语义） 照做

û = −g / |g| g = model.opt.gravity（默认 (0,0,−9.81)） â = xaxis[k] / |xaxis[k]| 世界系，mj_forward 之后可以直接读 c = |â · û| vertical: 通过 ⟺ c ≥ cos(τ) horizontal: 通过 ⟺ c ≤ sin(τ) τ = axis_angle_deg = 15°

这是唯一不需要物体坐标系的方向判定，而且整机绕竖直轴转一下结果不变—— 一个转了 90° 的正确柜子不会因此判负。它自己承认看不见更细的方向：抽屉往侧面滑和往外滑一样是水平的。

KF1.axis_admits_motion 轴向（走不走得通） 新增

更细的方向，唯一不依赖坐标系的证据：往这个方向走得通吗。

d₀ = 在 q_ref 处，部件与父件的最小带符号距离 若 d₀ < −ε: 记 N/A ← 已经卡在一起时的挡板 部件本来就埋在父件里的话，「往哪个方向动会不会撞」没有意义—— 每个方向都会撞。那是静态几何的账。 δ = min(0.25 × 行程, 0.05) q ← q_ref + δ × (声明的轴向) ; mj_forward d₁ = 移动之后的最小带符号距离 通过 ⟺ d₁ ≥ −ε ε = forbidden_penetration_m

反例：axis_rotated_90——抽屉往侧面滑，撞进左墙。 axis_semantic 看不见它（两个方向都是水平的），这条能抓住。

KF1.anchor 锚点 替换

on_edge_of（门、盖、翻板）

p₀ = xanchor[k], â = xaxis[k]/|xaxis[k]| r_i = (p_i − p₀) − ((p_i − p₀)·â) â 去掉沿着轴的那部分 d = r̄/|r̄|（质心方向）；|r̄| 接近 0 时改用 {r_i} 的主方向并去掉沿轴分量 s_i = r_i · d inset = min(|min s|, |max s|) / (max s − min s) 通过 ⟺ inset ≤ anchor_edge_inset_max = 0.15 0 = 轴线正好在边上 0.5 = 轴线在正中间
这条被换过一次，而且换掉的是「量法」不是「阈值」。 最早的量法是「同侧顶点占比 ≥ 0.95」。校准发现它是跳变的： 把已知正确的门铰链往里挪 1%，读数从 1.000 直接掉到 0.500；挪 2%、5%、50% 读数全是 0.500—— 一个盒子只有 8 个角，轴线一旦进到内部就永远是 4 对 4。真实资产读到的 0.69 / 0.75 / 0.83 / 0.91 只反映几何被拆成了几块，不反映轴线在哪。

更麻烦的是它把好坏排反了：摄像机的门读 0.50（全场最差），实际只往里 3.9%，是最干净的铰链； 钻床工作台读 0.80（看着还行），实际往里 27%，是真问题。

新量法经注入验证，跟位移线性对应，误差小于 0.005，且与几何拆成几块无关。 阈值 0.15 是从硬件推的：合页轴 15–25 mm、门宽 400–800 mm，往里 2–6%，所以 15% 已经很宽松， 25% 肉眼就看得出不是边缘铰链。没有从样本里挑——那是拿尺子迁就被量的东西。

through_center_of（轮子、齿轮、旋钮）

offset = |perp(部件质心 − p₀)| 通过 ⟺ offset / diag(AABB(部件)) ≤ anchor_center_offset_max = 0.05

归一化用部件自己的对角线，不用整机对角线——上一轮 607 条里只有 19 条能算出整机对角线。

KF1.range_and_reference 行程与参考 合并

span_model = jnt_range[k][1] − jnt_range[k][0] 通过 ⟺ |span_model − span_declared| / span_declared ≤ state_match_relative jnt_limited[k] = 0（URDF 的 continuous）→ 记 N/A

算一条，不是四条。states.closed、参考构型、range.min 常常是同一个数，而原方案把它们列成三件要分别核对的事。同一个数算三次， 正是 P0 自己那条「同一信息不重复计算」所禁止的。

KF1.rigid_follower 刚性随动 新增

R(b) = {b} ∪ { c : parent(c) ∈ R(b) 且 body_jntnum[c] = 0 } 不跨过任何关节能走到 通过 ⟺ b*(follower) ∈ R(b*(leader))

纯图上走一趟，不花钱，抓的是一个「看一眼看不出来」的缺陷： 把手螺在柜体上而不是抽屉上，在参考姿态下渲染出来一模一样，只有抽屉拉开时才露馅。 只在一个姿态上评估的检查看不见它，图上走一趟就能。

KF1.travel_scale 假关节 替换「可见部件不动」

D = diag(AABB(这个部件自己绑定的 geom)) 通过 ⟺ D / 行程 ≥ travel_scale_min = 0.50 只对 slide
原方案写的是：「不出现 qpos 变了而可见部件不动」—— 「可见」需要渲染，而 P3 自己的适用范围禁止渲染。它点名了人最容易说出口的那种失败 （「我拉开了，什么都没动」），却没有能用的算子。

要抓的是：body 挂着声明的关节、行程也对，但几乎没有几何，看得见的抽屉其实是不动部件的 geom。 位移测不出来——那个假部件把 0.18 m 走完了。能测的是尺寸：滑 0.18 m 而只有 8 mm 宽的东西，不是抽屉。 归一化用关节自己声明的行程，不用整机对角线。

量的是「部件自己」而不是「它带动的一切」——那个假部件上挂着一个真的 0.16 m 把手，整个刚性子树 0.39 m 宽，而契约点名的那个部件只有 0.0139 m。

05 · KF2

机械耦合保真度：4 条检查

先说公式为什么必须改。 原公式 KF2 = mean_g 1[max_q |r| ≤ ε] 读的是残差， 而残差只有在模型真的建了约束对象时才存在。生成器什么都没写 → 没有残差 → 空集取 max 让判断为真 → 最差的模型得 1.0。

正文里那句「检查 coupling 是否 active」本来是护栏，但真正落地的是公式。
KF2 = mean_g 1[bound(g)] × 1[ max_q |r_g,norm(q)| ≤ ε_g ]

前提：URDF 的 <mimic> 会被 MuJoCo 悄悄丢掉

实测：7 条真实资产声明了 <mimic>，加载后 neq 全是 0 （含传动比 −1 和 0.777778 的齿轮组、14 片联动的百叶窗、两个反向对转刀盘的碎纸机）。 不处理的话 KF2 会把这 7 条全判 0，理由是「没有实现耦合的约束」，可它们在 URDF 里写得完全正确—— 那等于让资产替读取方的缺陷背锅。

两条走 XML 的路都不通（URDF 里的 <mujoco><equality> 被忽略； mj_saveLastXML 存读一轮会丢几何），所以改成在编译前编辑 MjSpec。 URDF 的 q_dep = k·q_ind + c 和 polycoef 逐字段对应，翻译没有解释余地， 每次翻译都记进出处字段。

KF2.bound

E(g) = { e : eq_type[e] = mjEQ_JOINT 且 {eq_obj1id[e], eq_obj2id[e]} = {dep, ind} } 通过 ⟺ 存在 e ∈ E(g) 使 eq_active0[e] 为真

它绝不从「两个关节碰巧一起动」推出耦合存在。没有东西强制的关系不是关系， 不管某个姿态下数字多好看。

KF2.coefficient

MuJoCo: q_{obj1} = a₀ + a₁·q_{obj2} + a₂q² + a₃q³ + a₄q⁴ obj1 = dep: ĉ = a₁, ô = a₀ obj1 = ind: ĉ = 1/a₁, ô = −a₀/a₁ 角色互换 —— 同一个机构，不判负 通过 ⟺ |ĉ−c|/|c| ≤ ε 且 |ô−o| ≤ ε 且 max|a₂..a₄| ≤ 1e−9

符号是比值的一部分，不是约定。外啮合齿轮反着转，所以声明 −3 却建成 +3 描述的是一个造不出来的机构，这条会点名它「符号反了」，而不是报一个百分比。

KF2.expected_dof

n = Σ_{j∈成员} dof(jnt_type[j]) free=6, ball=3, slide=1, hinge=1 m = #{ e : eq_type=JOINT 且 active 且 {obj1,obj2} ⊆ 成员 } 通过 ⟺ n − m = expected_dof

它和 bound 从两个独立方向抓同一个缺陷：bound 读模型的约束表， expected_dof 数还剩几个自由度。骗过一个的模型，得换一种方式才能骗过第二个。

（数行数而不是取 efc_J 的秩，前提是这些行互相独立——单条等式必然成立；两条冗余等式会被高估， 这一点记为局限而不是掩盖，而语料里不会出现，因为耦合来自 <mimic>， MuJoCo 每个关节只允许一条。）

KF2.residual

对 q 取 linspace(range.min, range.max, 33) 含端点、奇数个所以含中点 qpos[ind] ← q qpos[dep] ← c·q + o ← 把模型摆到「它应该在的位置」 mj_forward(m, d) ← 只算位置，不步进，不涉及质量/摩擦/阻尼 rows = { i : efc_type[i]=EQUALITY 且 efc_id[i]=e } r(q) = max |efc_pos[rows]| R = max_q r(q) / N N ∈ {依赖端行程, 独立端行程, 绝对值} 通过 ⟺ R ≤ ε_g
齿轮箱构型max |efc_pos|含义
正确的 −30.000000两种描述完全一致
建成 −26.283输入转一圈，输出差一整圈
建成 +337.698差六圈——符号错比齿比错更离谱，读数也确实更大
没有约束N/A由 bound 判负，不由这条报「齿比错了」

没有约束时，coefficient 和 residual 不判，记 N/A。对一个根本不存在的关系报「齿比错了」 是把缺陷说错了名字——缺失是 bound 的账。

06 · KF3

四层采样：结果固定、成本可控、可查

原方案只写了「确定性的可行 q 采样」，没有任何采样规则。示例资产 3 个自由度， 满网格是 33³ = 35,937 个姿态，且随自由度指数增长（6 个自由度 = 13 亿）。 每个自由度单独扫很便宜，但对「两个抽屉同时拉开才会撞」完全看不见。

层内容换来什么柜子成本
参考q_ref基准1
① 逐自由度每个关节 33 个点，其余留在参考姿态单个动作会撞到的东西——绝大多数99
② 成对网格9×9，只对包围盒可能相交的那些对互相配合才出现的失败243
③ 状态组合声明的语义状态全组合 2^d（d>12 时封顶）人真正命名的那些姿态，精确访问8
④ Halton 填充256×d 个点规整的采样会跨过去的东西768
合计1,119

② 的筛选判据——「成本可控」就来自这里

B(j) = ⋃_{v ∈ {lo, 中点, hi}} AABB_保守( subtree(child(j)) 在 q_j=v 时 ) pad = 0.05 × max( diag B(a), diag B(b) ) 若 B(a) 与 B(b) 各自胀 pad 之后仍不相交 → 跳过这一对，并写进报告

用往大了取的包围盒（外接球半径）是有意选的方向：高估的代价是白扫一对， 低估的代价是漏掉这一层存在的理由。跳过了哪些对写进 pairs_skipped—— 悄悄少扫了，读起来和全扫过一模一样。

④ 用 Halton，不用 Sobol，更不用随机

φ_b(k) = Σ_{i≥0} d_i(k) × b^(−i−1) d_i(k) = k 写成 b 进制后第 i 位 第 k 个点的第 j 维 = φ_{p_j}(k) p = (2,3,5,7,11,13,…)

没有种子可设，因为压根没有抽签——第 k 个点是 k 的固定函数。 分数在两次运行之间会变的话，任何回归都和噪声分不开。 （Halton 到十维以上相关性变差，所以它是补充前面三层，不单独承担覆盖。这点记在代码里。）

两个容易搞反的地方

采样区间取契约声明的 range，不取模型的——用模型的区间等于把搜索悄悄缩到 资产恰好允许的范围，一个把行程写小的资产反而被扫得更松（写错是 KF1 的账）。

依赖关节的值由契约的耦合关系算出，不由模型的约束算出——把模型摆到 P0 说它该在的位置， 它自己的机构在那儿同不同意，是 KF2 的残差要回答的。

07 · KF3

可行运动一致性：3 条检查

先说原方案的「运动有效性」为什么大部分被换掉。 「closed/open/中间姿态可达」「轨迹连续」「相对位姿符合关节语义」—— 在编译好的 mjModel 上全是正向运动学自带的性质，而正向运动学按构造就是精确且连续的。 把姿态写进 qpos 永远成功。没有资产能让它们失败。

能失败的是到那儿的路上会不会撞自己，所以「可达」被改写成 「在不产生禁止穿模的前提下可达」——那才是关于资产的问题。

KF3.forbidden_pair 禁止对

Q = 采样点集合 exempt(q, 对) = 存在一条 required/permitted 声明，针对同一对，且 q 属于它声明的状态 pen(q) = max(0, −该对在 q 处的最小带符号距离) 这一对通过 ⟺ max_{q ∈ Q, 非 exempt} pen(q) ≤ forbidden_penetration_m S_forbidden = 通过的禁止对数 / 能算的禁止对数 能算的对数 = 0 → 记 N/A，不是 1.0
按对计分，不按样本。一千个姿态里有一个深度穿模，那是一对坏了。 除以样本数会读成 0.99997——同一个缺陷会随着采样密度在四个数量级之间移动。 姿态是证据（报出第一个出问题的 q），不是分母。

反例 swept_interference：在门的扫过区域里放一个支架。

门开角 与柜体最小间距 0° +0.00000 20° +0.00000 25° −0.00509 ✗ 30° −0.02791 ✗ 35° −0.01119 ✗ 40° +0.00000 90° +0.00000 两个端点都干净，只在中间撞。任何只在声明状态上检查的做法都会判它完美。

KF3.required_contact 必须接触

Q_s = { q ∈ Q : q 属于状态 s } 通过 ⟺ min_{q ∈ Q_s} d(a, b) ≤ required_contact_m Q_s 为空 → 记 N/A（从没被评估过的声明不等于被满足的声明）

这就是旧 allowed 桶里那半「永远不会失败」的东西被改成的样子。 作为「必须」，它抓的是只靠 range 属性限位、全身没有几何挡住的机构—— 那正是「真机构」和「只是声明了」的区别。标准柜子最初就有这个毛病，加了前挡边才修好。

KF3.state_reachability 状态可达

通过 ⟺ max_{q ∈ Q_s} max_{禁止对, 非 exempt} pen(q) ≤ forbidden_penetration_m

不是问「状态可不可达」——那是采样器的性质，不可能失败。 是问「能不能干净地停在那个状态」。

08 · 打分与报告

让判定能被追问

score(R) = |{ r ∈ R : 通过 }| / |{ r ∈ R : 不是 N/A }| 分母 = 0 → None，不是 1.0，也不是 0.0

两个极端都是在为一个没人测过的维度编一个结果出来。 分母为空的指标不是「测到了一个完美的资产」，是「什么都没测到」。

三种结论，不是两种

通过 / 失败 / N/A。N/A 必须存在，因为另一种做法更糟： 工具没法评估的声明记成通过，和它评估过并判定满足，完全分不开。 上一个项目把读不出来的字段当成缺失的字段，等于把读取方的缺口算到了资产头上。

报告拒绝写出三种会误导人的形状

拒绝为什么
判了失败但没写理由没法被追问的判定是一句话，不是证据
有结论但没有测量值同上
记了 N/A 但没说读不到什么扫表格的人分不清「没写理由的 N/A」和「通过」

每份报告必带出处和覆盖

provenance: {inertia_synthesized, mimics_translated, distance_backend, notes}
coverage:   {samples, by_layer, pairs_swept, pairs_skipped, scan_points, …}
tolerance_digest: sha256[:16]

出处：没人应该靠信任来相信「合成的惯量」和「补回来的耦合」没有混进分数。 覆盖：一个悄悄跳过一半姿态空间的采样计划，读起来和全扫过的一模一样。

KF1 按「怎么判出来的」分开报

KF1.declared = score(读字段类: type, range_and_reference) KF1.measured = score(其余全部)

上一轮语料里读字段类几乎全通过，混在一起会把真正会变的那些淹掉。 实测：range_too_small 上 declared=0.83 / measured=1.00， hinge_through_middle 上正好反过来。

09 · 验证

13 份标准资产：缺陷是人为造的，答案已知

为什么必须有它们。拿真实资产跑出来 0.87——这个数对不对没人知道。 而最糟的情况是一条永远不会失败的检查：它在所有资产上都输出「通过」， 看起来像「资产都挺好」，不像「代码坏了」。真实资产本来大部分就是通过的，两者长得一模一样。 没有已知的坏输入，这种检查根本看不出来。
资产 KF1 KF3 查出来的 cabinet_correct 1.00 1.00 — wrong_parent 0.96 1.00 KF1.parent wrong_joint_type 0.91 0.89 KF1.type + range（单位随类型变） hinge_through_middle 0.96 1.00 KF1.anchor axis_rotated_90 0.96 1.00 KF1.axis_admits_motion range_too_small 0.96 1.00 KF1.range_and_reference detached_follower 0.96 1.00 KF1.rigid_follower fake_joint_decoy_geom 0.95 1.00 KF1.travel_scale door_axis_horizontal 0.91 0.89 KF1.axis_semantic + anchor swept_interference 1.00 0.89 KF3.forbidden_pair gearbox_correct KF2=1.00 — gearbox_wrong_ratio KF2=0.50 KF2.coefficient + residual gearbox_wrong_sign KF2=0.50 同上（符号反了） gearbox_missing_coupling KF2=0.00 KF2.bound + expected_dof ← 原公式会给 1.00

每条检查要过三关，不是两关：正确件上不响 · 自己的反例上响 · 别人的反例上不响。 第三关是「一条检查」和「烟雾报警器」的分界——什么坏了都响的检查没有查出父件错了，只查出「有东西不一样」。

反例存成「对正确件的最小修改」（120 条逐检查的预期写在清单里），所以缺陷是能读的 diff。 匹配不到任何东西的替换会直接报错——否则「反例」就和对照件一模一样， 拿它测出来的检查看着可靠、实际什么都没查。

光是把正确件建出来，就当场抓到 5 个 bug（真实资产一个都发现不了）： loader 用子串搜 <inertial 而注释里正好写了这几个字、包围盒用外接球高估了一整个半对角线、 门轴绕 +z 转导致往柜子里面开、穿进去 0.040 m、门把手埋在自己门板里，以及—— 对照件本身有「只靠 range 限位、没有几何挡住门」的问题，正是 required_contact 要抓的那类。

11 · 边界

还没解决的四件事

① C5：把关节约束拿掉，几何撑不撑得住

P3 这三项加起来都问不到这个问题。一扇声明了完美 revolute 关节、 一根合页几何都没有的门，KF1/KF2/KF3 全绿——求解器会无条件替资产执行关节约束。

而这在人工标注里是失败最多的一项：425 条里 103 条，比第二名多十倍。 上面的实测已经证实了这一点：rec_stove_top_0002 P3 每一项 1.00、零失败， 人工总评却只有 3 分。

现有的东西里有它的两块碎片（travel_scale、required_contact）， 但都没问到它的核心问题。已按决定推迟；做的时候作为单独命名的扩展项，不进 Kinematic Profile， 两张表并排报。

② 部件粒度对不上

十条真实资产里，生成器的部件划分普遍比提示词粗：曲柄脚踏把主轴、两个曲柄臂、链轮焊成一个 crank_assembly；灶台没有任何 burner link；吊扇把四个叶片合并进 rotor。

已裁定：数目和提示词不一致就算失败，Gate 拒掉它们是正确行为。 这条裁定还消掉了一个误报——曲柄脚踏那条「父件错」是绑定有损造成的，人工判它全部满足， 而在这条裁定下它根本到不了 P3。

但吊扇那条值得单独看：它的 N/A 有 27 条（十条里最多），因为每一条点名叶片的接触声明都绑不上， 23 条接触声明里只评了 5 条。粒度问题卡住的，恰好是本来最该起作用的那类检查。

③ P0 的两个表达缺口

缺口在哪暴露的
数量不定的复数：去掉 count 之后没法表达「若干个按键」 笔记本资产有 48 个独立按键 link，契约一个都没声明 → 48 个真实自由度无人评估
由几何决定的比值：没法表达「这些联动，比值由几何定而不是由声明定」 手套箱门的四连杆——门与限位连杆的比值提示词没给，只能声明「两根连杆彼此 1:1」

④ range_and_reference 触发 7/10，可疑

多半是同一类原因：契约里那些行程数字，不少是提示词没给、由契约作者填的 （笔记本的 2.1 rad 就在契约注释里注明了是作者判断）。 这需要的是逐条复核契约，不是改检查。

还有一条一直存在、只能靠人解决的：契约由谁写。 判分过程是纯计算没错，但契约本身是写出来的文字。哈希冻结防的是「看了资产再改契约」， 防不了「一开始就把提示词读错」——钻床那条，契约作者把「standard locking features」 （复数、没给数）写成了 1 个锁柄，资产实际有 2 个。那是契约作者的错，不是资产的错，也不是检查的错。 所以流程必须是：起草 → 逐条签字 → 再冻结。
